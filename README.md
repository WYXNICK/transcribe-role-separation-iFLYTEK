# README

## 项目概述

本仓库为2025 iFLYTEK AI开发者大赛面向说话人转写内容的角色分离挑战赛亚军解决方案代码。本项目实现了一个完整的语音角色分离与转写系统，旨在解决多人自由对话交流场景下的精准转写和内容角色分离问题。系统通过级联的深度学习管线，实现了从原始音频到角色标注文本的端到端处理。

### 核心功能
- **语音活动检测（VAD）**: 识别音频中的语音段和静音段
- **说话人分离（Speaker Diarization）**: 将音频分离为不同说话人的片段
- **自动语音识别（ASR）**: 将语音转换为文本
- **角色标注**: 为每个文本片段标注对应的说话人身份
- **评估系统**: 基于word-DER指标的性能评估

## 技术架构

### 系统整体流程
```
原始音频 → VAD → Speaker Diarization → 音频切分 → ASR → 角色标注文本
```

### 核心技术栈
- **深度学习框架**: PyTorch 2.8.0 + PyTorch Lightning
- **说话人分离**: pyannote.audio + 3D-Speaker
- **语音识别**: FireRedASR (AED/LLM variants)
- **文本处理**: jieba分词 + 自定义中文处理
- **评估指标**: word-DER (词级别说话人分离错误率)

### **技术实现详解**

本系统的核心是一套精心设计的级联式处理管线，它将原始的、包含多人对话的音频文件，通过一系列先进的深度学习模型和算法，最终转化为带有说话人身份标注的精确文本。整个流程实现了高度的自动化和模块化，确保了处理的高效性与结果的准确性。

#### **1. 语音活动检测（VAD）模块**

**目标**：精确地从连续的音频流中识别出包含人类语音的片段，同时过滤掉静音或背景噪音部分，这是后续所有处理步骤的基础。

**技术方案**：
系统优先采用业界领先的 `pyannote.audio` 框架中经过预训练的语音活动检测模型。该模型基于深度学习，能够在复杂的声学环境中稳健地工作。

**实现细节与优化**：
- **模型加载与设备管理**：系统启动时会自动加载 VAD 模型。为了最大化处理效率，它会检测是否存在可用的 NVIDIA GPU，如果存在，则自动将模型和计算任务迁移至 CUDA 设备上运行，从而实现显著的加速。
- **鲁棒性设计 (Fallback机制)**：考虑到模型加载可能因网络或环境问题失败，系统内置了一套备用方案。当 `pyannote` 模型无法使用时，系统会自动切换到一种基于音频能量的VAD算法。该算法通过计算音频的短时能量（RMS Energy）并与动态设定的阈值进行比较，来判断语音的存在，保证了系统在任何情况下的可用性。
- **后处理与片段优化**：VAD的原始输出可能会产生一些琐碎的短小片段。为了提升后续处理的效率和准确性，系统对VAD结果进行了精细的后处理：
    - **语音段合并**：对于间隔非常近（例如小于0.3秒）的两个独立语音段，系统会将其智能地合并为一个连续的语音片段，以保持对话的连贯性。
    - **最小时长过滤**：系统会过滤掉时长过短（例如小于0.6秒）的语音片段，这些片段通常是无效的噪音或非语音声音，去除它们可以减少后续模块的计算负担和潜在错误。

#### **2. 说话人分离（Speaker Diarization）模块**

**目标**：在检测到的语音片段基础上，进一步区分出是哪一位说话人在讲话，即“谁在什么时间说话”。

**技术方案**：
本项目的核心优势之一是集成了强大的 **3D-Speaker** 开源工具包。该方案基于先进的说话人嵌入（Speaker Embedding）技术，能够为每个语音片段提取出具有高度区分性的声纹特征。

**实现细节与优化**：
- **声纹提取与聚类**：系统首先使用在大量中文通用语音数据上预训练的 `speech_campplus_sv_zh-cn_16k-common` 模型（如 CAM++）来提取每个语音片段的声纹向量。然后，通过高效的谱聚类（Spectral Clustering）算法，将相似的声纹向量（即来自同一说话人的片段）聚合在一起，从而完成说话人的区分。
- **动态参数调整**：为了适应不同复杂度的音频场景（例如，不同数量的说话人），系统支持在运行时动态调整聚类算法的关键参数，如聚类阈值、预设的最小和最大说话人数等，这大大增强了系统的灵活性和准确性。
- **结果优化**：与VAD类似，说话人分离的直接输出也需要优化。系统会对属于同一说话人的、时间上邻近的短小片段进行合并，形成更长、更自然的语句片段。同时，它也会根据预设的时长窗口（如8秒）来控制合并的粒度，避免将不相关的对话错误地连接在一起。

#### **3. 自动语音识别（ASR）模块**

**目标**：将经过VAD和说话人分离处理后的、归属于特定说话人的纯净语音片段，准确地转换成文本。

**技术方案**：
系统集成了高性能的 **FireRedASR** 模型，这是一个工业级的中文ASR解决方案，提供了两种针对不同需求的架构变体：
- **FireRedASR-AED**：基于注意力机制的编码器-解码器（Attention-based Encoder-Decoder）架构。这种架构在通用场景下具有非常高的识别准确率和稳定性。
- **FireRedASR-LLM**：一种创新的、与大语言模型（LLM）相结合的ASR框架。它不仅能识别语音，还能更好地理解上下文语义，在处理复杂或口语化表达时具有优势。

**实现细节与优化**：
- **动态模型选择**：用户可以在系统配置中轻松切换使用 `AED` 或 `LLM` 变体，以适应不同的应用场景和性能要求。
- **高效批量推理**：为了最大化吞吐量，ASR模块被设计为支持批量处理。它可以一次性接收多个音频片段，并行进行识别。
- **智能内存管理**：系统能够智能地处理大批量的转写任务。当待处理的音频片段数量过多，可能导致GPU显存溢出时，系统会自动将大批量任务切分成多个小批次（Chunked Batching）进行处理，并在每个批次处理后主动清理GPU缓存。这种机制在保证速度的同时，极大地提升了系统的稳定性。
- **文本后处理**：识别出的原始文本会经过一系列的后处理步骤，包括去除多余的空格、修正常见的重复词（如“我我我”）、以及弱化语气词（如“啊啊啊”）等，使得最终输出的文本更加干净、规范和易读。

#### **4. 数据预处理模块**

**目标**：为系统的评估和潜在的优化任务，提供结构化的、标记好的数据。

**技术方案**：
此模块主要负责解析标准的语音标注文件 `TextGrid`，并将其与对应的音频文件进行关联和处理。

**实现细节**：
- **TextGrid文件解析**：系统能够深度解析 `TextGrid` 文件，提取出每一段语音的精确起止时间、说话人标识以及对应的文本内容。它能智能地从标注文件的层（Tier）名或文本内容中自动识别并提取说话人ID。
- **音频切分与对齐**：基于从 `TextGrid` 中解析出的时间戳，该模块使用 `librosa` 和 `soundfile` 等专业音频处理库，将原始的长音频文件精确地切分成与文本标注一一对应的小音频片段。在切分过程中，还会对时长过短或过长的片段进行过滤，确保数据质量。
- **数据集构建**：处理完成的数据会被整理成结构化的 `DataFrame`（使用 `pandas` 库），并可以根据需求被划分成训练集和验证集，为后续的系统评估和性能分析提供便利。

#### **5. 评估系统**

**目标**：客观、量化地评估系统在说话人分离任务上的表现。

**技术方案**：
系统采用 **词级别说话人分离错误率（word-level Diarization Error Rate, word-DER）** 作为核心评估指标。相比传统的基于时间的DER，word-DER能更直观地反映在转写文本中，因说话人识别错误导致的词语错误。

**实现细节**：
- **中文文本处理**：为了精确计算word-DER，系统首先使用 `jieba` 分词库对参考文本和系统输出文本进行分词。分词前，还会进行文本清洗，如移除标点符号和特殊字符，以保证分词的准确性。
- **词级别时间对齐**：系统通过一种近似算法，将每个词语均匀地映射到其所在语音段的时间轴上，为每个词估算出一个大致的起止时间。
- **错误计算**：通过对比参考文本和系统输出文本中每个词的说话人标签，系统会精确计算出三类错误：
    - **混淆错误（Confusion）**：词语正确，但说话人标签错误。
    - **插入错误（Insertion）**：系统输出了参考文本中没有的词。
    - **删除错误（Deletion）**：系统未能输出参考文本中存在的词。
- **生成评估报告**：最后，系统会基于上述错误统计，计算出最终的word-DER，并生成一份包含总体指标和各文件详细指标的评估报告。

#### **6. 超参数优化**

**目标**：为系统的核心模块（主要是说话人分离和ASR）找到最佳的运行参数组合，以达到最优性能。

**技术方案**：
系统集成了一套自动化的超参数搜索框架，主要采用网格搜索（Grid Search）的策略。

**实现细节**：
- **参数空间定义**：系统预先定义了需要优化的关键参数及其可能的取值范围。例如，对于说话人分离，参数空间可能包括聚类阈值、最小/最大说话人数；对于ASR，则可能包括束搜索（Beam Size）的宽度、各种惩罚项（如长度、重复度）的权重等。
- **自动化评估**：优化器会自动遍历参数网格中的每一种组合，使用验证集数据来运行完整的处理管线，并基于预设的评估指标（如word-DER）对该参数组合的性能进行打分。
- **寻找最优解**：在完成所有参数组合的评估后，系统会找出性能得分最高的那一组参数，并可以将其保存为新的配置文件，供后续的推理任务使用。这一自动化流程极大地简化了系统调优的过程。

## 安装和使用

### 1. 环境安装
```bash
# 安装依赖
pip install -r requirements.txt

# 下载预训练模型
# FireRedASR模型需要从HuggingFace下载
# 3D-Speaker模型会自动从ModelScope下载
```

### 2. 数据准备
```bash
# 训练数据格式：
# xfdata/eval/
#   ├── E1.wav
#   ├── E1.TextGrid
#   ├── E2.wav
#   ├── E2.TextGrid
#   └── ...

# 测试数据格式：
# xfdata/test_data/
#   ├── T1.wav
#   ├── T2.wav
#   └── ...
```

### 3. 训练模型
```bash
cd code
bash train.sh
```

### 4. 运行推理
```bash
# 完整管线
python main.py --mode full

# 仅推理
python main.py --mode inference

# 仅评估
python main.py --mode evaluate
```

### 5. 配置文件
系统支持JSON格式的配置文件，主要参数：
```json
{
  "data": {
    "eval_dir": "../xfdata/eval",
    "test_dir": "../xfdata/test_data",
    "output_dir": "../user_data/tmp_data/processed_data",
    "val_split": 0.0
  },
  "pipeline": {
    "diarization": {
      "clustering_threshold": 0.5,
      "min_speakers": 2,
      "max_speakers": 8
    },
    "asr": {
      "model_name": "FireRedASR-AED",
      "beam_size": 3,
      "length_penalty": 0.8,
      "repetition_penalty": 1.0,
      "temperature": 0.1
    }
  }
}
```

## 故障排除

### 常见问题
1. **CUDA内存不足**: 降低batch_size或使用CPU模式
2. **模型下载失败**: 检查网络连接和HuggingFace token
3. **音频格式不支持**: 转换为16kHz 16-bit PCM WAV格式

### 性能调优
1. **GPU利用率**: 调整batch_size和num_workers
2. **内存使用**: 启用梯度累积和混合精度训练
3. **推理速度**: 使用TensorRT或ONNX优化
